# 飞鸽局域网聊天设计

日期：2026-10-28

## 目标

做一个 Java 8 Web 应用。局域网里的人在浏览器中打开服务地址，注册账号后可以在公共大厅聊天，也可以两人私聊，并互相传文件。聊天记录和文件都保存在运行机器上。最终只部署一个可执行 jar。

默认管理账号可以删除指定用户（连带该用户的消息和文件），也可以一键清空全部聊天记录和全部文件。

## 已定决策

- 运行时：Java 8，Spring Boot 2.7.18，可执行 fat jar。
- 数据库：H2 文件库。
- 实时消息：WebSocket，JSON 文本帧，不使用 STOMP。
- 页面：HTML、CSS、JavaScript 打进 jar，不需要单独的前端构建。
- 聊天形态：一个公共大厅，加上两人私聊。
- 管理清理：按用户删除，以及一键清空全部聊天记录和文件。
- 默认管理员：用户名 `admin`，密码 `admin123`。第一次启动时若不存在则创建。普通注册不能使用该用户名（大小写不敏感）。

## 不做的事

已读回执、撤回、群组、头像、端到端加密、自动发现局域网里的服务。用户自己输入服务地址。

## 架构

浏览器只连接这一台服务。页面、登录、历史消息、上传和下载走 HTTP。新消息走 WebSocket。

服务监听 `0.0.0.0:8080`，局域网其他机器可以用 `http://<主机IP>:8080` 访问。端口可用 `server.port` 或 `--server.port` 修改。

进程内四块：

- 静态页面。
- HTTP 接口：注册、登录、会话和历史、上传下载、管理操作。
- WebSocket：每个已登录用户一条或多条连接。大厅消息推给所有在线用户。私聊只推给双方。
- 存储：H2 保存账号、会话和消息。上传文件放在数据目录的 `files/` 下。

数据目录：

- 用 `java -jar feige.jar` 启动时，数据目录是 jar 所在目录下的 `data/`。
- 从 IDE 或 `classes` 目录启动时，数据目录是当前工作目录下的 `data/`。

```text
feige.jar
data/
  feige.mv.db
  files/
```

登录使用服务端 Session，Cookie 为 HttpOnly。密码只存 BCrypt 哈希。CSRF 使用 Cookie 令牌：服务写入 `XSRF-TOKEN`，浏览器请求带上 `X-XSRF-TOKEN`。

## 页面

- `/login`：用户名、密码。已登录用户打开此页时进入聊天页。
- `/register`：用户名、密码。成功后进入登录页。
- `/chat`：聊天页。未登录访问时回到登录页。
- `/admin` 不再作为独立页面：管理员登录后，在聊天页左下角点击账号，菜单中的「管理设置」以浮窗展示管理功能。

聊天页布局：

- 左侧最上是「大厅」，下面是其他用户。在线用户排在前面，名字旁有在线标记。
- 点击大厅或某个用户，右侧切换到对应会话。
- 右侧上方是历史消息，底部是文本输入框、选择文件和发送按钮。
- 文字消息显示发送人和时间。文件消息显示原始文件名和大小，点击后下载。
- WebSocket 断开时，输入框上方显示「连接已断开，正在重连」。重连成功后才允许发送。未发送的文字留在输入框中。

管理设置（仅 `admin`，聊天页浮窗）：

- 列出除 `admin` 以外的用户：用户名、注册时间、删除按钮。
- 一个按钮：「清空全部聊天记录和文件」。
- 删除和清空之前都要浏览器确认。

## 账号

- 用户名 2 到 20 个字符，只允许字母、数字和汉字，正则 `^[\p{L}\p{N}]{2,20}$`。全局唯一，比较时忽略大小写。`admin` 保留。
- 密码 6 到 64 个字符。库中只存 BCrypt 哈希。
- 角色只有 `ADMIN` 和 `USER`。注册创建的都是 `USER`。

## 会话与消息

- 大厅只有一个，类型 `HALL`，首次启动时创建。所有已登录用户都可以查看和发言。
- 私聊类型 `DIRECT`。任意两个普通用户之间最多一条。第一次点击对方时创建，之后一直使用这一条。`admin` 也可以作为普通参与者聊天。
- 打开会话时用 HTTP 拉取全部历史，按时间从早到晚显示。
- 文字由客户端经 WebSocket 发送。服务先写入数据库，再推给该会话中在线的接收方。大厅的接收方是所有在线用户。私聊的接收方是双方中在线的连接。发送者自己的其他标签页也要收到，以便多标签一致。
- 文件先经 HTTP 上传。保存成功并写入消息后，服务再按同样规则推送一条文件消息。
- 一个人可以开多个标签页。每个标签页一条 WebSocket。全部连接关闭后才变为离线。在线状态变化推送给所有在线用户。
- 没有已读、撤回和编辑。

## 文件

- 单个文件上限 100MB。空文件拒绝。
- 磁盘文件名是随机 UUID，不使用客户端传来的文件名，避免重名和路径穿越。原始文件名、大小、上传者只存在数据库中。
- 下载响应使用 `Content-Disposition: attachment`，文件名使用数据库中的原始文件名（UTF-8）。
- 大厅文件：任何已登录用户可下载。私聊文件：只有该私聊的两名参与者可下载。
- 文件一直保留，直到管理员删除对应用户或执行清空。

## 管理员动作

删除指定用户，在一个事务中完成：

1. 找出该用户参与的全部私聊。
2. 删除这些私聊中的全部消息（含对方发送的），以及该用户在大厅中发送的全部消息。
3. 删除这些消息对应的磁盘文件。
4. 删除这些私聊及其成员关系。
5. 删除该用户。
6. 大厅和其他人的大厅消息保留。
7. 事务提交后关闭该用户尚在的连接，并通知其他在线客户端：该用户已移除，相关私聊已删除。

不能删除 `admin`。

清空，在一个事务中完成：

1. 删除全部消息。
2. 删除 `data/files/` 中的全部上传文件。
3. 删除全部私聊及其成员关系。
4. 保留全部账号，保留大厅会话（大厅变为空）。
5. 事务提交后通知在线客户端刷新为空的大厅，并去掉私聊历史。

## 数据模型

`users`

| 列 | 说明 |
| --- | --- |
| id | 主键 |
| username | 唯一，存原始大小写；唯一索引使用小写 |
| password_hash | BCrypt |
| role | `ADMIN` 或 `USER` |
| created_at | 创建时间 |

`conversations`

| 列 | 说明 |
| --- | --- |
| id | 主键 |
| type | `HALL` 或 `DIRECT` |
| created_at | 创建时间 |

`conversation_members`

| 列 | 说明 |
| --- | --- |
| conversation_id | 外键 |
| user_id | 外键 |
| 约束 | `(conversation_id, user_id)` 唯一 |

大厅不写成员行，成员身份由「已登录」决定。私聊恰好两行。创建私聊时在应用层按用户 id 升序加锁，保证同一对用户不会建出两条。

`messages`

| 列 | 说明 |
| --- | --- |
| id | 主键 |
| conversation_id | 外键 |
| sender_id | 外键 |
| kind | `TEXT` 或 `FILE` |
| body | 文字内容，或文件的原始文件名 |
| stored_name | 仅 `FILE` 有值，磁盘上的 UUID 文件名 |
| size_bytes | 仅 `FILE` 有值 |
| created_at | 创建时间 |

文字消息的 `body` 去掉首尾空白后不能为空，最长 2000 个字符。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/register` | JSON：`username`、`password`。成功 201 |
| POST | `/login` | 表单登录，成功后进入 `/chat` |
| POST | `/logout` | 退出并回到 `/login` |
| GET | `/api/me` | 当前用户 id、用户名、角色，以及大厅会话 id |
| GET | `/api/users` | 其他用户：id、用户名、是否在线。在线的在前 |
| POST | `/api/conversations/direct` | JSON：`userId`。返回已有或新建的私聊 |
| GET | `/api/conversations/{id}/messages` | 该会话全部消息。调用者必须是参与者；大厅对所有已登录用户开放 |
| POST | `/api/conversations/{id}/files` | `multipart` 字段名 `file`。成功后返回文件消息 |
| GET | `/api/files/{messageId}` | 下载该文件消息。权限与查看该会话相同 |
| GET | `/api/admin/users` | 普通用户列表。仅 admin |
| DELETE | `/api/admin/users/{id}` | 删除该用户及其关联数据。仅 admin |
| POST | `/api/admin/clear` | 清空全部消息和文件。仅 admin |

未登录调用 `/api/**` 返回 401。非 admin 调用 `/api/admin/**` 返回 403。

## WebSocket

地址：`/ws`。握手时必须带有已登录 Session，否则拒绝。

客户端发送：

```json
{"type":"send","conversationId":1,"text":"你好"}
```

服务端推送：

```json
{"type":"message","message":{"id":1,"conversationId":1,"senderId":2,"senderName":"张三","kind":"TEXT","body":"你好","sizeBytes":null,"createdAt":"2026-10-28T15:00:00Z"}}
```

```json
{"type":"presence","userId":2,"username":"张三","online":true}
```

```json
{"type":"user.deleted","userId":2}
```

```json
{"type":"conversations.deleted","conversationIds":[3,4]}
```

```json
{"type":"cleared"}
```

```json
{"type":"error","message":"连接已断开前的说明，或发送失败原因"}
```

文件消息的 `kind` 为 `FILE`，`body` 是原始文件名，`sizeBytes` 是字节数。客户端用 `/api/files/{messageId}` 下载。

客户端断线后自动重连，间隔从 1 秒递增，上限 10 秒。重连成功后重新拉取当前打开的会话历史，补上断线期间错过的消息。

用户被删除时，服务关闭该用户尚在的 WebSocket。

## 错误表现

| 情况 | 结果 |
| --- | --- |
| 用户名已存在或是保留名 `admin` | 400，提示「用户名已存在」 |
| 用户名或密码不符合长度和字符规则 | 400，提示具体规则 |
| 登录失败 | 停留登录页，提示「用户名或密码错误」 |
| 未登录访问聊天、管理页 | 网页跳转登录页 |
| 未登录调用接口或 WebSocket | HTTP 401，WebSocket 握手拒绝 |
| 普通用户打开管理页或管理接口 | 403 |
| 删除 `admin` | 400，账号保留 |
| 文件超过 100MB 或为空 | 400，不写盘，提示原因 |
| 向无权访问的会话发消息或上传 | 403 |
| 下载无权访问的文件，或磁盘文件已丢失 | 403 或 404 |
| 发送时空文本，或超过 2000 字 | WebSocket 错误消息，不入库 |

## 测试

自动测试使用内存 H2，不读写项目外的真实 `data/` 目录。临时上传目录用测试专用文件夹，测试结束删除。

覆盖：

- 注册成功、用户名重复、不能注册 `admin`、密码过短。
- 登录失败不区分是用户名错误还是密码错误。
- 同一对用户只产生一条私聊。
- 私聊消息只推给双方，第三名在线用户收不到。
- 删除用户会删除他的大厅消息、他参与的私聊（含对方消息）以及对应磁盘文件；其他人的大厅消息还在；`admin` 不能被删除。
- 清空会删除全部消息、全部私聊和全部磁盘文件；用户和大厅会话还在。
- 普通用户调用管理接口得到 403。
- 非参与者不能下载私聊文件。

自动测试通过后，在本机执行 `java -jar`，用两个浏览器完成：注册、大厅发言、私聊、发送小文件、管理员删除用户、管理员清空。

## 验收

1. 只复制一个 jar 到一台机器，执行 `java -jar feige.jar` 即可启动。
2. 局域网内至少两台设备的浏览器可以注册并同时聊天。
3. 大厅和私聊的文字、历史记录在刷新或重新登录后仍然存在。
4. 文件出现在 jar 同级 `data/files/`，对方可以下载到原始文件名。
5. `admin` / `admin123` 可以删除指定用户，也可以清空全部聊天记录和文件。
